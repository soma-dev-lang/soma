# RFC 0002 — the law: business rules outside the code, and code held to them

- Status: draft, for review by the language owner before any implementation
- Edition: any release (additive: new file kind, new clauses that were syntax errors, a new command)
- Diagnostic codes added: E0150–E0156 (proposed, below)

## Problem

Soma proves that the flesh keeps to the skeleton. It proves nothing about
whether the skeleton does what the business requires, because nothing says
what the business requires.

Gérance (`site/cases/gerance`, a UCITS fund system, 12,000 lines) shows it.
Its skeletons declare 0 invariants, 0 postconditions, 0 properties; its
flesh holds 442 `require`. `soma verify` said `VERIFY OK` from the first day
to the last while 118 scenario tests found over a hundred business defects.
Three in a row were one rule, defended one forgotten path at a time:

| Scenario | "No payment to a frozen holder" was missing in |
|---|---|
| S104 | the settlement of a redemption |
| S105 | the payment of a distribution |
| S106 | the payment of an indemnity after a NAV error |

Nothing listed the places where a payment is made, so nothing could say
that the rule was served in one and not in the others.

A fourth defect was not a missing check but a wrong model: the order book
required a counterparty at order entry, when an order goes to an execution
system and the counterparty is known only at execution. The compiler
checked that wrong model with care. The fund manager saw it in ten seconds
once it reached a screen — it had never been written anywhere he could
read it.

## Change

Three artefacts, three reviewers, and a compiler that holds each to the one
above it.

| | Holds | Written and reviewed by |
|---|---|---|
| Law | terms and rules of the business, in sentences | the business expert |
| Skeleton | memory, state machines, frames | the architect |
| Flesh | the code | the programming agent |

### 1. The law is a file of its own, and knows no code

A `.law` file names no cell, no handler, no test. It can be written before
the program exists, and more than one program can be held to it.

```
law Sanctions

term Porteur  "Celui qui détient des parts, inscrit au registre."
term Paiement "Un versement d'espèces du fonds à un porteur."
term Souscription "L'entrée d'un porteur dans une classe de parts."

rule "SAN-01" "Aucune souscription d'un porteur bloqué"
    about  Souscription, Porteur
    source "Règlement (UE) 269/2014, art. 2"
    owner  "conformite"

rule "SAN-02" "Aucun paiement vers un porteur bloqué"
    about  Paiement, Porteur
    source "Règlement (UE) 269/2014, art. 2"
    owner  "conformite"

rule "SAN-06" "Le déblocage d'un porteur est motivé et fait par un autre que celui qui l'a bloqué"
    about  Porteur
    source "Procédure LCB-FT, § 4.3"
    owner  "conformite"
```

`about` lists the terms a rule speaks of; every term it names must be
declared. A rule may later carry a formal clause over terms (`never …
while …`); that is a second step and not part of this RFC.

`soma law lock` writes `law.lock`. A law that differs from its lock fails
the check, as a skeleton does: changing the law is an event someone
reviews.

### 2. The program says which laws it is under

In `soma.toml`:

```
[law]
files = ["lois/sanctions.law"]
```

### 3. The code is aligned on the law — three clauses, all in the code

**`realizes`**, on a signal of a skeleton: this action is an instance of a
term of the law.

```
skeleton PasOrdre {
    face {
        signal regler(par: Utilisateur, date: Date, p: String) -> String
            realizes Paiement
```

**`under`**, on what serves a rule: a `require`, a guarded edge of a state
machine, a test cell.

```
require etat_p != "bloque" else Bloque "{porteur} est bloqué" under "SAN-02"

moves valorise -> regle when PasPorteur.valide via porteur_de under "SAN-02"

cell test PaiementDUnPorteurGele under "SAN-02" { rules { … } }
```

**`exempt`**, in the skeleton, with a reason: this rule does not apply to
this action.

```
        signal payer(par: Utilisateur, date: Date, f: Fonds) -> Map
            realizes Paiement
            exempt "SAN-02" "paie la société de gestion, pas un porteur"
```

### 4. What the compiler checks

For a program under at least one law:

| Code | Refused |
|---|---|
| E0150 | an `under` or `exempt` naming a rule no law of the program declares |
| E0151 | a `realizes` naming a term no law declares; an `about` naming an undeclared term |
| E0152 | a rule served by nothing: no `under` anywhere in the program |
| E0153 | a rule about a term, and a signal that realizes that term with neither an `under` for the rule in its handler (or on one of its edges) nor an `exempt` |
| E0154 | a rule with no test `under` it |
| E0155 | a law that differs from `law.lock` |
| E0156 | an `exempt` without a reason |

E0153 is the one that would have reported S104, S105 and S106 together:

```
error: rule "SAN-02" (Aucun paiement vers un porteur bloqué — Règlement (UE)
269/2014, art. 2) is not served in VlCorrection.verser, which realizes
Paiement — add a refusal `under "SAN-02"` to it, or `exempt "SAN-02"
"<why it does not apply>"` on its signal
  = code: E0153
```

A warning, not an error: a `require` under no rule, in a program under a
law (W0020). It lists the business logic nobody declared.

### 5. `soma law`

- `soma law app.cell` — the conformity table, in the order of the law:
  each rule, its source, where it is served, its tests, its status
  (`proved` on every path by a guarded edge / `checked` at run time by a
  `require` / `tested` only / `unserved`).
- `soma law app.cell "SAN-02"` — the file of one rule: its text, its
  terms, every signal that realizes them, every place that serves it,
  its tests. One screen instead of a search through the flesh.
- `soma law app.cell --todo` — only what fails, as a work list.
- `--json` on each.

### 6. Written for a programming agent

The agent is the first reader of all this.

- **A work list it does not have to imagine.** `--todo` names the rule, the
  signal and the fix. E0153 is an instruction, not a finding to interpret.
- **A file per rule.** An agent's context is summarised and lost; the file
  of a rule is rebuilt on demand, small, and complete.
- **It cannot invent a rule.** The law is locked; an agent that needs a
  rule proposes it (a `proposed` rule, which serves nothing until a person
  accepts it and relocks).
- **Its assumptions are written down.** When the law is silent on a fact
  the agent needs, it records an `assume "ORD-A1" "La contrepartie d'un
  ordre est connue à la saisie"` in the law's companion file
  `*.assumptions`, cited `under` like a rule and shown first in the table
  with the status `unreviewed`. A person strikes it or promotes it. That
  sentence, written down, is what would have exposed the order-book model.
- **A definition of done.** The table is green or it is not.

### 7. The refusal witness (second step, own RFC)

A tag proves nothing by itself. For each `require … under R`, the compiler
removes it and runs the tests under R: one must fail. Otherwise the rule is
`unwitnessed`. This is "red test first", made mechanical. It needs the test
runner to run a modified program, and is left to RFC 0003.

## Migration

None: a program with no `[law]` table is unchanged. Gérance would add
`lois/sanctions.law` (6 rules), 5 `realizes`, about 8 `under`, and its
tests' cell headers.

## Measured effect

- Repository programs that change verdict: 0 of 3,442 (none has a `[law]`
  table; `realizes`, `under`, `exempt` are syntax errors today).
- To be measured on the pilot (Gérance, sanctions): how many of the 6 rules
  are served on every signal that realizes their terms — in particular
  whether the conversion between share classes and the detachment of a
  distribution, never checked by a scenario, are.
- Agent benchmark: a task "add a payment path" with and without the law,
  measuring whether the agent serves SAN-02 on it.

## Open choices for the language owner

1. Keywords in English (`law`, `term`, `rule`, `about`, `source`, `owner`,
   `realizes`, `under`, `exempt`, `assume`), like the rest of Soma — or
   another vocabulary.
2. Rule identifiers as strings (`"SAN-02"`), because of the hyphen — or
   identifiers (`SAN_02`).
3. Whether E0154 (a rule with no test) is an error from the start or a
   warning until the refusal witness exists.
4. Whether `realizes` belongs on signals only, or also on memory slots and
   states (a term that is a thing, not an action: `Porteur`).

## Alternatives considered

- **Do nothing.** The proof stays about consistency; scenarios stay the
  only defence, and depend on what the agent thinks to imagine.
- **The law names the code** (`refuses Bloque in PasOrdre.regler`,
  `witnessed by <test>`). Rejected by the language owner: the law must
  exist before the code and outside it; the code is aligned on the law,
  never the reverse.
- **Tags only, no terms.** Catches an unserved rule (E0152), not a
  forgotten path (E0153): three of the four defects above were forgotten
  paths.
- **A full ontology** (classes, inheritance, inference). Grows to describe
  the world instead of serving the program. A term enters only if a rule
  or a `realizes` uses it.
- **A rules file and a script outside the compiler.** Enough for a pilot;
  it cannot refuse a program, so it does not hold an agent to anything.
