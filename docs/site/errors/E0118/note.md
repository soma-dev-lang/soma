A `tool` bound to a server (`[openapi: "pets/getPetById"]` or `[mcp: "docs"]`) has no `on` handler: the server answers it, so its declaration must match the contract that `soma tools sync` pinned in soma.lock, and the server must be defined in soma.toml under `[tools.<name>]`. `soma check` compares the two offline and reports E0118 for a server soma.toml does not define, a tool soma.lock does not pin, or an argument the server does not take, of the wrong type, or left out. Parameter names are the server's, so `pet_id` must be written `petId` as the OpenAPI document declares it.
