When a cell declares a signal in its `face`, the `on` handler for it must take the same parameter types in the same order; `soma check` reports E0092 at the face signal when a position differs (here the face says `cents: Int` and the handler says `cents: Float`). Callers, `soma describe` and HTTP clients follow the face, while the handler's body runs with its own declaration, so the two must agree. Fix whichever side is wrong; a mismatch in a parameter's name alone is only a warning.
