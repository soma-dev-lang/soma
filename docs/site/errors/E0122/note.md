Two nominal types (`cell type Lots = Int`, `cell type Cents = Int`) never mix: adding, comparing or passing one where the other is declared is refused, and so is a plain `Int` variable where a `Lots` is declared. Here a cap in cents is applied to a position in lots; with plain `Int` everywhere, `soma check` passes and `soma verify` even proves the bound, on the wrong quantity. Declare the cap in what it counts (`const MAX_LOTS = Lots(50)`), or write the conversion (`Cents(to_int(lots) * to_int(price))`); a literal (`lots <= 50`, `?? 0`) takes the type of the other side. The type is erased after `soma check`: at run time, in storage and in JSON a `Lots` is an `Int`, and `soma verify` proves the same things.
