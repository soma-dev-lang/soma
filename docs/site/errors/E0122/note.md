Two nominal types (`cell type Lots = Int`, `cell type Cents = Int`) never mix: adding, comparing or passing one where the other is declared is refused, and so is a plain `Int` variable where a `Lots` is declared. Here a cap in cents is applied to a position in lots; with plain `Int` everywhere, `soma check` passes and `soma verify` even proves the bound, on the wrong quantity. Declare the cap in what it counts (`const MAX_LOTS = Lots(50)`). Two nominal types name two different things: where one is given for the other — as an argument, a value stored, a field of a record or of a variant, the key of a `Map<Id, …>` — get the right one from what links them in the program (a lookup, a signal). Write the conversion (`Cents(to_int(lots) * to_int(price))`, `Id(to_string(key))`) only where the value already IS of the other type, by construction: a conversion written to silence the check keeps the defect; a literal (`lots <= 50`, `?? 0`) takes the type of the other side. The type is erased after `soma check`: at run time, in storage and in JSON a `Lots` is an `Int`, and `soma verify` proves the same things.
