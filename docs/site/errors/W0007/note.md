`soma check` warns with W0007 when the slot named by `scale { shard: … }` is marked `[consistent]` while the scale section says `consistency: eventual`: the slot promises to read its own writes, but under eventual consistency a read after a write may return stale data. Eventual is the only consistency the cluster runtime implements (`soma verify` fails `consistency: strong`, and the cluster mode of `soma serve` refuses it), so the fix is to drop `consistent` from the sharded slot and write the handlers to tolerate stale reads.
